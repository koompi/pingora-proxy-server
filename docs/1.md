## Introduction

Pingora Proxy Server is a high-performance reverse proxy and load balancer built on Rust's Pingora framework. It provides HTTP/HTTPS routing, automatic SSL certificate management via Let's Encrypt, and deep integration with Docker Swarm for service discovery and network isolation.

### Key Features

- HTTP to HTTPS redirection
- Automatic SSL certificate management with Let's Encrypt
- Wildcard certificate support with Cloudflare DNS integration
- Docker Swarm integration for service discovery
- Organization-based network isolation in Swarm environments
- RESTful API for configuration management
- Real-time metrics and Prometheus integration
- Distributed locking for multi-node deployments

## Architecture Overview

The system consists of several interconnected components:

- **HTTP Proxy**: Handles HTTP requests, redirects to HTTPS, and serves ACME challenges
- **HTTPS Proxy**: Routes HTTPS traffic to backend services
- **Manager Proxy**: Provides a REST API for configuration management
- **Docker Swarm Discovery**: Automatically discovers services in Swarm environments
- **Certificate Manager**: Handles certificate issuance and renewal with Let's Encrypt
- **Certificate Watcher**: Monitors for certificate changes across nodes

The proxy runs on a shared configuration store that can be updated dynamically via the API or through service discovery.

## Installation

### Using Docker

```bash
docker run -d --name pingora-proxy \
  -p 80:80 -p 443:443 -p 81:81 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /mnt/gluster/certbot:/certbot \
  -v /mnt/gluster/certbot/letsencrypt:/etc/letsencrypt \
  -v /mnt/gluster/acme-challenge:/var/www/html/.well-known/acme-challenge \
  -v /mnt/gluster/proxy-config:/app/config \
  -v /mnt/gluster/pingora-proxy/locks:/pingora-proxy/locks \
  -v /mnt/gluster/pingora-proxy/cert_requests:/pingora-proxy/cert_requests \
  image.koompi.org/library/pingora-proxy-server:latest
```

## Configuration

### Basic Configuration

The proxy is configured through a JSON file located at the path specified by the `CONFIG_PATH` environment variable (defaults to `/app/config/config.json`).

Basic configuration example:

```json
{
  "servers": [
    {
      "from": "example.com",
      "to": "192.168.1.213:3040"
    },
    {
      "from": "koompi.com",
      "to": "192.168.1.213:4444"
    }
  ]
}
```

### Environment Variables

| Variable               | Description                                    | Default                       |
| ---------------------- | ---------------------------------------------- | ----------------------------- |
| `CONFIG_PATH`          | Path to the configuration file                 | `/app/config/config.json`     |
| `DISABLE_SSL`          | Set to "true" to disable HTTPS                 | `false`                       |
| `SWARM_MODE`           | Enable Docker Swarm integration                | `false`                       |
| `SWARM_NETWORKS`       | Comma-separated list of networks to monitor    | `ingress`                     |
| `DOCKER_ENDPOINT`      | Docker API endpoint                            | `unix:///var/run/docker.sock` |
| `LOG_LEVEL`            | Log level (trace, debug, info, warn, error)    | `info`                        |
| `CLOUDFLARE_API_TOKEN` | Cloudflare API token for wildcard certificates | -                             |

## API Reference

The proxy exposes a REST API on port 81 for configuration management.

### Domain Mapping Management

#### List Domain Mappings

```
GET http://localhost:81/
```

**Response:**

```json
{
  "status": "success",
  "mappings": [
    {
      "from": "example.com",
      "to": "192.168.1.213:3040",
      "origin": "Manual"
    },
    {
      "from": "koompi.com",
      "to": "192.168.1.213:4444",
      "origin": "SwarmDiscovery"
    }
  ]
}
```

#### Add or Update Domain Mapping

```
POST http://localhost:81/example.com/192.168.1.213:3040
```

**Response:**

```json
{
  "status": "success"
}
```

#### Delete Domain Mapping

```
DELETE http://localhost:81/domain/example.com
```

**Response:**

```json
{
  "status": "success"
}
```

### Certificate Management

#### Request a New Certificate

```
POST http://localhost:81/certificates
```

**Request Body:**

```json
{
  "domain": "example.com",
  "email": "admin@example.com"
}
```

**Response:**

```json
{
  "domain": "example.com",
  "status": "issued",
  "cert_path": "/certbot/letsencrypt/live/example.com/fullchain.pem",
  "key_path": "/certbot/letsencrypt/live/example.com/privkey.pem",
  "expiry": "SystemTime { tv_sec: 1719846523, tv_nsec: 0 }",
  "is_wildcard": false
}
```

#### Request a Wildcard Certificate

```
POST http://localhost:81/certificates
```

**Request Body:**

```json
{
  "domain": "example.com",
  "email": "admin@example.com",
  "wildcard": true,
  "dns_provider": "cloudflare",
  "dns_credentials": {
    "api_token": "your_cloudflare_api_token"
  }
}
```

#### Check Certificate Status

```
GET http://localhost:81/certificates/status/example.com
```

**Response:**

```json
{
  "domain": "example.com",
  "status": "valid",
  "cert_path": "/certbot/letsencrypt/live/example.com/fullchain.pem",
  "key_path": "/certbot/letsencrypt/live/example.com/privkey.pem",
  "expiry": "SystemTime { tv_sec: 1719846523, tv_nsec: 0 }",
  "is_wildcard": false
}
```

#### Reload Certificates

```
POST http://localhost:81/admin/reload_certs
```

**Response:**

```json
{
  "status": "success",
  "message": "Certificate reload completed successfully. All nodes will pick up changes within 15 seconds."
}
```

## Certificate Management

The proxy automatically manages SSL/TLS certificates using Let's Encrypt.

### Standard Certificates

For standard domain certificates, the proxy uses the HTTP-01 challenge method, which requires:

1. The domain must resolve to the proxy's public IP
2. Port 80 must be accessible for the ACME challenge

### Wildcard Certificates

For wildcard certificates (e.g., `*.example.com`), the proxy uses the DNS-01 challenge method with Cloudflare DNS:

1. Set the `CLOUDFLARE_API_TOKEN` environment variable
2. Request a wildcard certificate through the API

### Manual Certificate Operations

You can manually request or renew certificates using the `certbot-wrapper.sh` script:

```bash
# Request a standard certificate
./certbot-wrapper.sh request-standard example.com admin@example.com

# Request a wildcard certificate
./certbot-wrapper.sh request-wildcard example.com admin@example.com your_cloudflare_token

# Renew all certificates
./certbot-wrapper.sh renew
```

## Docker Swarm Integration

When `SWARM_MODE` is enabled, the proxy automatically discovers and configures routes for services with the following labels:

- `com.koompi.proxy=true` - Enables proxy for this service
- `com.koompi.proxy.domain` - Domain name for this service
- `com.koompi.proxy.port` - Port to route to (defaults to 80)
- `com.koompi.org.id` - Organization ID for network isolation

Example Docker Compose service with Swarm labels:

```yaml
services:
  web:
    image: nginx:alpine
    deploy:
      labels:
        com.koompi.proxy: "true"
        com.koompi.proxy.domain: "example.com"
        com.koompi.proxy.port: "80"
        com.koompi.org.id: "100"
```

## Network Isolation

The proxy supports creating isolated overlay networks for different organizations in a Docker Swarm environment.

### Organization Networks

Each organization gets its own isolated overlay network with format `org_{org_id}_overlay`. Services in the same organization can communicate with each other, but communication between organizations is blocked.

The `setup-network-isolation.sh` script handles:

1. Creating organization-specific overlay networks
2. Applying network policies to services
3. Setting up firewall rules for isolation

## Monitoring and Metrics

The proxy collects and exposes metrics for monitoring in Prometheus format on port 9100.

### Available Metrics

- `proxy_requests_total` - Total number of proxy requests
- `proxy_request_duration_seconds` - Request duration in seconds
- `certificate_operations_total` - Total number of certificate operations
- `backend_failures_total` - Total number of backend failures

### Grafana Integration

The Docker Compose file includes Prometheus and Grafana for monitoring. Access Grafana at `http://localhost:3005` with default credentials `admin/admin`.

## Troubleshooting

### Common Issues

**Certificate Renewal Failures**

- Check if port 80 is accessible from the internet
- Verify that domain DNS records point to the proxy's IP
- Examine logs in `/var/log/certbot-wrapper.log`

**Service Discovery Issues**

- Verify Docker socket is mounted correctly
- Check service labels for proper formatting
- Check the Docker Swarm network connectivity

**Proxy Connectivity Issues**

- Verify backend services are running and accessible
- Check firewall rules and network policies
- Examine `RUST_LOG` output for detailed error information

### Logs

The proxy logs can be accessed through Docker:

```bash
docker logs pingora-proxy
```

For detailed logging, set `LOG_LEVEL=debug` and `RUST_LOG=pingora=debug`.
